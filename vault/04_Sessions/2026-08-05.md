# 2026-08-05 — Kp coverage and orbit restart

The four-worker Halley run reached 99% before failing because the bundled GFZ
Kp series ended at 2001-12-31 while the IMAGE inputs continue through June
2003. The GFZ download now contains 10,464 definitive three-hour values from
2000-01-01 through 2003-07-31. The previously failing
`2002-01-01T00:01:08` frame matches Kp 2.333 in the interval beginning at
00:00.

The Kp loader retains cadence, definitive-status, range, and thirds-scale
checks. It calculates the loaded file's SHA-256 for provenance instead of
requiring source code to contain the expected bytes or record count.

Orbit processing now uses atomic output files for restart. Valid final files
are skipped by default; missing and invalid products are rerun. Each new file
is written and validated as `.partial` before an atomic rename. A separate
completion ledger was rejected because it could diverge from the products.

Verification: all 45 repository tests passed. The focused tests include Kp
coverage and matching, dynamic checksum provenance, restart selection,
structural output validation, atomic publication, and preservation of an
existing final file after a simulated write failure.
