# Session — FUVVIEW3 calibration and WIC reflat clarification

Last reviewed: 2026-08-26

## Result

Ohma et al. (2024) explicitly use FUVVIEW3-processed IMAGE data and state that
the camera images are corrected for lifetime temperature and voltage changes.
Flat-field correction is part of that upstream processing for each camera.
This weakens the hypothesis that the high WIC/SI13 ratios simply result from a
missing SI13 flat field.

fuvpy's `reflat` option is a separate WIC-only repair. The original row-dependent
flat field scales both the physical WIC signal and its large constant detector
background. The revised operation removes the constant level, flat-fields the
signal, and restores the constant afterward. Ohma et al. did not observe the
same row artifact in SI12 or SI13, probably because their constant backgrounds
are small. Passing `reflat=True` for an SI camera has no effect in the code.

The remaining calibration question is narrower: the exact FUVVIEW3 version,
correction functions, calibration-flag meanings, and numerical relative
WIC/SI13 gain scale have not been verified for the local IDLs. Ohma et al.
support that standard corrections were applied, but do not independently
validate the cross-camera count scale required by the Frey energy inversion.
The empirical conclusion is unchanged: the present ratio retrieval fails and
an alternative E0 source is required.

## Reflat and additive-SI13 sensitivity

The visual increase in central WIC brightness in Ohma et al. Figure 2 is not a
uniform gain. Algebraically, the new and old operations differ by
`C * (1 - FF)`, so the sign and magnitude vary across detector rows. Figure 2
also precedes the fitted residual-background removal. A fair comparison must
therefore refit that background separately for each flattening convention.

This comparison was made on the native detector images for orbits 0085, 0086,
and 0968, using identical SI mapping, smoothing, proton correction, and a
common post-proton signal mask. Enabling reflat changed the median WIC/SI13
ratio by +2.4%, -0.9%, and +2.0%, respectively. The fraction above the Frey
limit changed from 55.29% to 56.17%, 45.61% to 45.25%, and 17.65% to 18.91%.
The large-ratio failure therefore remains under the original FUVVIEW3
flattening, although reflat can amplify individual weak residuals.

SI13 count-scale sensitivity is much larger. Holding the original full-corpus
guard fixed, adding 1, 2, 3, 5, or 10 counts to corrected SI13 reduces the
out-of-Frey fraction from 14.48% to 10.50%, 7.86%, 6.04%, 3.81%, and 1.56%.
These offsets are diagnostic perturbations only. They demonstrate that a few
counts can dominate the inversion near the present denominator threshold; they
do not establish a missing constant or authorize adding one in production.

## Flat-field database provenance

`fuvpy/utils/wic_flatfield_dbase.idl` was not generated by fuvpy. Embedded IDL
metadata records `2015-03-25`, user `hfrey`, and a SunOS/SPARC host. The file
contains two float32 WIC detector-row profiles with shape `(256, 2)`, labeled
`2000/255` and `2001/205`. Anders Ohma first added the unchanged binary to the
fuvpy repository in 2021. There is no derivation or uncertainty in fuvpy.

Frey et al. (2003), section 7, state that low-altitude dayglow was used to
derive flat fields: WIC deviations were fitted while SI corrections were kept
in a lookup table. Frey et al. (2017) describe an approximately 30% central SI
sensitivity loss corrected during quantitative processing. Østgaard et al.
(2018) additionally report using an updated SI13 flat field because the default
performed poorly on their event's dayside. Therefore SI12/SI13 calibration
tables existed.

The FUVVIEW3 tree used by the dataset producer was subsequently recovered at
`/home/bing/Downloads/fuview3/fuview3`. `KALLES_README` is an installation
recipe from 2008 and does not state the export choices. The support directory
contains active flat-field databases with shapes `(256, 4)` for WIC,
`(128, 12)` for SI13, and `(128, 3)` for SI12. `get_flatfield.pro` treats the
year/day labels as calibration dates, splits the database at the spacecraft
boom loss on day 278 of 2000, and selects the nearest profile on the relevant
side. Later observations therefore retain the nearest older calibration. The
fuvpy cutoff is the same boom-loss boundary, not an applicability limit.

FUVVIEW3 calibration flag 1 means corrected counts and applies the selected
flat field and mission-sensitivity factor. The mission database covers
2000--2005. A file named `new_si_flatfield_dbase.idl` is present but is not
referenced by the active code. fuvpy's two WIC profiles are a simplified subset
of the four-profile FUVVIEW3 database and omit its post-boom rotation and row
shift, so its reflat operation is not an exact inverse. Local SI IDLs carry
flag 1; the WIC value 3 is not defined in this FUVVIEW3 version and remains a
generation-provenance question.

## Recovered-FUVVIEW3 sensitivity result

A standalone diagnostic now tests six calibration branches on raw example
IDL images: original inputs, current fuvpy, current fuvpy with the apparent
intended WIC mask parentheses, recovered WIC, recovered WIC+SI13, and recovered
WIC+SI13+SI12. It ports the recovered profile-date selection and post-boom
geometry, refits the fuvpy background independently for each sensor and
variant, maps SI footprints onto native WIC detector pixels by area overlap,
applies the 2-keV proton correction, and compares branches on fixed all-pixel
and nightside supports.

The recovered calibration does not solve the ratio problem. The original
statistics in this session used point interpolation for SI-to-WIC mapping and
were superseded on 2026-08-27 by the area-overlap rerun. On fixed nightside
support, the corrected recovered-all branch changes the current-fuvpy median
ratio by `+6.18%`, `+3.17%`, and `-0.91%` for orbits 0085, 0086, and 0968. The
fraction beyond the Frey limit changes by `+2.73`, `+1.17`, and `+0.03`
percentage points. Applying the SI profiles therefore worsens the first two
examples and has little effect on the third.

The isolated SI comparison is unambiguous: adding recovered SI13 to recovered
WIC increases the 90th-percentile ratio and the above-Frey fraction in all
three examples. Adding SI12 afterward changes the result negligibly. The ratio
maps were revised to show the full corrected WIC and SI13 images, categorize
missing, excluded, and retained pixels, and report retained versus paired
pixel counts for the densest comparison frame. The script also accepts
`--plot-frame ORBIT:INDEX` for an explicit zero-based choice. Orbit 0968 was
regenerated with frame index 2; only three raw example frames are available
for that orbit.

The test also confirms that fuvpy's WIC background mask is parsed differently
from its apparent intent because parentheses are missing. This changes the
estimated WIC constant substantially in the two 2000 examples, but the
independent background refit leaves the final ratio almost unchanged. It is
not the cause of the failed retrieval.

The experiment is explicitly a recovered-FUVVIEW3 sensitivity rather than an
exact producer reconstruction. The available source does not define WIC
`CALIBRATION_FLAG=3` or `CIMAGE`; WIC and SI SAVE files have different export
eras; and the post-boom Python rotation/shift has not been validated against
an IDL/GDL golden output. No production code was changed. The reusable script
is `scripts/debugging/test_fuview3_reflattening.py`; results are under
`figures/debugging/fuview3_reflattening/`.
