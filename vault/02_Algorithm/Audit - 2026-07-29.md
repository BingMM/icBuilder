# icBuilder audit — 2026-07-29

Last reviewed: 2026-07-29  
Repository snapshot: `main` at `8e509ea` with unrelated uncommitted
Zhang–Paxton work

## Scope and verdict

This was a read-only scientific, numerical, pipeline, and reproducibility
audit of the current code and the five tracked example conductance products.
No production data were regenerated and no implementation was changed.

**Verdict:** the repository is a useful research prototype, but the current
pipeline and products are not publication-ready. The Frey et al. response
table is transcribed in the correct WIC/SI13 orientation and the interpolation
equation is not the obvious failure. The current E0 fields are instead
dominated by hard fallbacks and saturation. Several confirmed implementation
problems amplify the WIC/SI13 mismatch, while calibration provenance and the
fixed-atmosphere/viewing assumptions remain the most important unresolved
causal boundary.

## Confirmed WIC/SI13 findings

### The ratio problem precedes the E0 inversion

For orbit 0085, the binned uncorrected WIC/SI13 ratio for SI13 above three
counts has a median near 208, already above the response-table maximum of
about 136.5. The fixed proton correction raises the comparable median to about
244. Historical notes independently record excessive ratios before
background subtraction. The inversion cannot recover physical energy from
most such pixels.

Across the five tracked conductance products, only about 1.7–11.2% of valid
pixels are genuine interpolations inside the response-table domain. Most E0
values are exact constants produced by low-signal rules or bounds: 0.2, 1, or
25 keV. In orbit 0085 those constants account for about 98.3% of valid E0
values. Roughly 98–99.8% of pixels set to 25 keV also have dE0 equal to zero
because constant extrapolation has zero derivative. The stored dE0 therefore
expresses false certainty at upper saturation.

### Confirmed pipeline amplifiers

- WIC is binned at nominal 225 km, whereas SI13 is binned at 450 km and
  linearly interpolated back to the WIC grid. This does not restore SI13
  spatial detail and can compare narrow WIC arcs with spatially averaged
  SI13.
- The original 450-km grid was constructed from WIC cell centres rather than
  edges. It spanned 37.06 fine cells instead of 36, shifted corresponding
  centres by 9–121 km (median about 88 km), and made SI cells roughly
  4.7–6.0% too large. **Resolved in the current uncommitted work:** the user
  changed the bounds to the outer WIC mesh edges. An independent numerical
  check found that the resulting 18-by-18 SI edges are exactly every second
  edge of the 36-by-36 WIC grid and that each SI centre is the midpoint of the
  corresponding pair of WIC centres.
- Independent zero clipping, an SI13 threshold at three counts, and discrete
  low-signal fallbacks bias and discontinuously classify weak-denominator
  pixels. In the tracked products, roughly 26–38% of finite SI13 cells are
  exactly zero.
- Proton contamination is corrected using a globally fixed 2-keV proton
  characteristic energy with dEp equal to zero. The response is strongly
  proton-energy dependent. This increases already-high ratios in four of the
  five examples and can become unstable as corrected SI13 approaches zero.
- WIC uses the SH background estimate while SI12 and SI13 use DG. A matched
  comparison on orbit 0085 indicates this choice is not the primary cause,
  but it changes weak-signal boundaries.

These effects materially affect local ratios, classifications, and
uncertainties. They do not by themselves explain why the strong-signal raw
ratio is already outside the empirical response range.

**Priority clarification:** mapping SI into WIC image space is part of the
published IMAGE-FUV method and is not intrinsically wrong; the published
workflow also coregistered corresponding fields of view and smoothed both
channels. The malformed nested grid remains a real implementation defect, but
correcting it changed the representative orbit-0085 global ratio statistics
only modestly. Treat it as a required correctness fix, not the leading E0
explanation. If Zhang–Paxton replaces ratio-derived E0, weak-SI13 fallback
behavior is no longer a primary-product E0 problem and matters only if SI13 is
retained for validation.

## Most important unresolved causal boundary

The fixed Frey relation assumes a particular instrument calibration,
precipitating spectrum, reference atmosphere, and viewing geometry. The
published method explicitly requires temporal sensitivity correction and
reports that disturbed-atmosphere oxygen can suppress SI13, raise WIC/SI13,
and produce unreasonably high inferred energy.

icBuilder reads image values through fuvpy, requests a WIC flat-field
correction, and then discards calibration flags, detector voltages, source
metadata, and viewing angle before inversion. It neither applies nor records
an explicit temporal WIC/SI gain normalization. The raw example files contain
calibration and high-voltage metadata, but their upstream semantics are not
documented in this repository.

The user identified the upstream dataset as the IMAGE product prepared by
Karl Laundal and associated with Østgaard et al. (2018). That paper states
that its FUV images were exported from FUVIEW3 using **corrected counts**,
which include detector flat-field correction and a mission-time/temperature
correction. It also reports using an updated SI13 flat field for the studied
event. This substantially reduces the earlier concern that the upstream
values might be uncorrected raw counts, although the exact recipe and whether
the user's complete dataset uses the updated SI13 flat field still need to be
recorded as product provenance.

It is therefore **confirmed** that calibration state and response-table
compatibility cannot be audited from the generated products. It is only a
**hypothesis**, not yet proof, that the input images lack the required
temporal normalization. Applying one fixed standard-atmosphere, effectively
nadir response to frames admitted out to 75 degrees detector zenith angle is
a separate confirmed model-assumption mismatch.

The first causal experiment should reproduce one carefully selected,
strong-signal, near-nadir event using documented calibrated instrument values,
matched WIC/SI13 resolution and support, and an explicit atmosphere
assumption. Until that succeeds, tuning the E0 interpolation is not a useful
diagnostic.

### Follow-up inspection of fuvpy and viewing angle

The local `fuvpy` checkout (`main` at tagged version 3.0.0) confirms the
processing boundary:

- `read_idl` copies `IMAGEINFO.IMAGE` into `img`, reads geometry, masks static
  bad detector regions, and excludes pixels at or above the requested DZA
  limit. It does not read or preserve calibration flags, high-voltage state,
  exposure, or temporal-gain metadata.
- For WIC only, `reflat=True` applies one of two row-dependent flat fields,
  selected before/after 2000-10-03 23:30, after estimating a scalar background.
  No analogous new SI flat field is applied by this loader.
- `backgroundmodel_BS` uses
  `cos(solar_zenith_angle) / cos(detector_zenith_angle)` to model dayglow.
  This is a geometry-dependent background model, not a correction of auroral
  counts to their nadir-equivalent response.
- fuvpy contains an optional counts-to-kR conversion, but icBuilder does not
  call it. No explicit temporal-sensitivity normalization is present.

Thus, fuvpy is likely receiving FUVIEW3 corrected counts rather than
uncorrected detector values. The source paper establishes flat-field and
mission-time/temperature correction for that product; neither fuvpy nor
icBuilder preserves enough provenance to verify the exact upstream recipe
from a generated conductance file.

The `dzalim=75` call is only an inclusion mask: pixels with DZA below 75
degrees remain available. The Frey electron-response simulations were
line-of-sight integrations for a nadir observation. At 75 degrees an idealized
plane-parallel path-length factor is `1/cos(75 degrees) = 3.86`; real spherical
geometry and structured aurora make the relation more complicated.

An exploratory orbit-0085 calculation put both WIC and SI13 on the same
225-km grid and progressively restricted both input cameras by DZA. For
strong pixels (`WIC > 50`, `SI13 > 3`), the median uncorrected ratio changed
from about 56 at DZA below 30 degrees, to 93 below 45 degrees, 130 below 60
degrees, and 156 below 75 degrees. The fraction above the response-table
maximum rose from 13% to 33%, 47%, and 58%, respectively.

This trend is diagnostic, not causal proof: each cutoff changes geographic and
auroral sampling, and the near-nadir subset is much smaller. It nevertheless
shows that the permissive 75-degree selection deserves a controlled test.
Compare the same locations observed at changing DZA, or stratify by
MLAT/MLT/intensity, before attributing the trend to viewing geometry alone.
This issue remains relevant after replacing ratio-derived E0 because
WIC-derived Fe still assumes a response per vertical incident energy flux.
Do not apply a simple DZA correction without validation. In an idealized
optically thin plane-parallel layer, a slant radiance scales approximately as
`1/cos(DZA)`, so conversion to a nadir equivalent would multiply by
`cos(DZA)`, not divide by it. The real aurora is vertically extended,
structured, curved, and wavelength-dependent; absorption and the projected
footprint also change with angle. First determine whether the upstream
FUVIEW3 `IMAGE` product already includes any applicable correction, then test
a geometry-aware correction against controlled observations.

### Østgaard et al. (2018) processing and the LOS boundary

The paper confirms three distinct processing operations: FUVIEW3 corrected
counts (flat-field plus mission-time/temperature correction), an updated SI13
flat field for the event, and a per-image dayglow/background model based on
solar and satellite zenith angle. The zenith-angle dependence in the
dayglow model is not a normalization of the residual auroral signal.

The paper explicitly warns that very oblique auroral intensities differ from
nadir observations in a structure-dependent way. It does not give or apply a
quantitative auroral line-of-sight correction. Instead, it avoids that
requirement by comparing sufficiently bright feature morphology rather than
absolute intensities. icBuilder cannot inherit that escape because it uses
WIC intensity to infer vertical incident electron energy flux and
conductance.

The physically complete correction belongs in the instrument/atmosphere
forward response: replace the nadir response `Wm(E0)` with a response
`Wm(E0, DZA, atmosphere, geometry)` and invert the observed slant intensity
with that response. Frey et al. (2003) state that their tabulated electron
emissions were integrated for a nadir spacecraft observation, using MSIS-90
under moderately disturbed conditions. A universal scalar cosine correction
therefore cannot reproduce that full transfer function.

For a controlled first-order diagnostic, the optically thin,
horizontally-uniform plane-parallel approximation gives
`W_vertical ~= W_slant * cos(DZA)`. This correction should be applied to
individual dayglow-subtracted pixels before spatial binning, not to an
already-binned cell with mixed viewing angles. It may be defensible over a
validated moderate-DZA range, with more oblique pixels flagged or excluded
from quantitative flux retrieval while remaining usable for morphology.
Because the same idealized secant factor would cancel from a perfectly
coregistered WIC/SI13 ratio, this simple correction cannot by itself repair
the former E0 ratio retrieval; wavelength-dependent absorption and emission
altitude require the angle-dependent forward model. After the planned
Zhang–Paxton replacement, LOS still affects WIC-derived Fe.

### Review of the provisional SZA/DZA implementation

The current uncommitted `PreImage` change correctly loads the lowercase `sza`
and `dza` variables from all three representative sensor NetCDF files. Their
shapes match the image arrays, their units are degrees, and the provisional
plane-parallel operation multiplies the background-subtracted pixel values by
`cos(DZA)` before binning. That is the correct direction and ordering for the
first-order diagnostic.

The implementation is not yet suitable as the production default:

- `BinnedImage(..., los_correction=True)` defaults to enabling an unvalidated
  scientific approximation, and the production script explicitly enables it
  for WIC, SI12, and SI13.
- A blanket cosine correction is especially unsafe for SI12, whose
  Doppler-shifted Lyman-alpha response depends on viewing geometry and the
  emitting-particle velocity distribution, not only geometrical path length.
- **Resolved at the binned-image level:** `BinnedImage` now retains the median
  SZA, median DZA, median `cos(DZA)`, and the selected LOS-correction flag. The
  geometry uses the same valid source pixels as the image statistic and is
  carried through target-grid interpolation and frame selection.
- **Resolved:** `PreImage.discard` now subsets raw `img` along with the
  processed images, coordinates, weights, SZA, and DZA.
- **Resolved in the current uncommitted work:** with no SH/DG correction
  selected, `BinnedImage` now uses the raw-image LOS accessor when
  `los_correction=True`. A functional one-frame check confirmed that the raw
  corrected and uncorrected branches differ as intended.
- The multiplication treats the LOS approximation as exact and adds no
  geometry/model contribution to uncertainty.

For orbit 0085 frame 0, a direct WIC comparison found 802 mutually finite,
positive bins. The ratio of cosine-corrected to uncorrected binned WIC had
5th, 50th, and 95th percentiles of 0.296, 0.623, and 0.932. This is a large
scientific change and must be explicit, channel-specific, recorded in output
provenance, and validated before regeneration of publication products.

Two focused binned-geometry regression tests pass alongside a
ConductanceImage NetCDF round-trip test and the seven Zhang–Paxton-collapse
tests. Representative WIC and interpolated SI13 checks also confirmed that
SZA, DZA, and the LOS factor have the expected target-grid shape.
`ConductanceImage` now copies all three geometry fields separately for WIC,
SI12, and SI13 and serializes the nine arrays with units. Each sensor's
image-correction mode and LOS-applied flag are recorded as file attributes.

## Uncertainty and numerical correctness

The user explicitly deferred uncertainty redesign for later work; preserve the
following findings for that checkpoint.

- Binned-image uncertainty is not the uncertainty of the median. It combines
  a mean-based t standard error with an upper population-standard-deviation
  bound, interpolates standard deviations, and later adds Poisson terms to
  corrected binned medians.
- WIC and SI13 corrections share SI12 and proton-energy uncertainty, but the
  ratio propagation treats the corrected channels as independent.
- Fe depends on both corrected WIC and E0, yet `ConductanceImage` sets the
  E0–Fe covariance to zero.
- Robinson zero-flux uncertainty substitutes a minimum from a different
  nonzero-flux state and can yield NaN or division by zero at some energies.
- `SplineImage.solverP` passes Hall uncertainty `dH` to the Pedersen solver
  instead of `dP`. This is a confirmed secondary-product bug and is explicitly
  deferred for later correction.
- `PreImage.discard` does not subset the raw image array. The current SH/DG
  production path avoids this branch, but the public API is unsafe.
- `ConductanceImage` recomputes the complete weight cube once per output
  pixel, producing avoidable quadratic work.

## Reproducibility and maintenance

- `pyproject.toml` declares no runtime dependencies, despite eager imports of
  the scientific stack.
- The only automated tests are the seven uncommitted Zhang–Paxton-collapse
  tests; the main IMAGE/conductance pipeline has no regression tests or CI.
- Primary scripts execute substantial work at import time, contain hard-coded
  paths or multiprocessing choices, and can overwrite generated outputs.
- Generated NetCDF products omit enough source, calibration, unit,
  configuration, sample-count, and retrieval-status metadata to prevent a
  forensic reconstruction.
- The repository contains about 719 MB of tracked example data. The local Git
  object store reports about 5.10 GiB of loose objects plus 500 MiB of packs.
- Several ancillary figure and VAE scripts contain independent path, labeling,
  or dimension errors. These are not causal for the conductance products but
  indicate limited end-to-end test coverage.

## What holds up

- The Frey electron response nodes and WIC/SI13 ratio direction are correctly
  transcribed.
- The five tracked example orbits have WIC/SI12/SI13 acquisition differences
  of only 0–1 seconds, so the two-second matcher is not the observed E0 cause.
- Apex conversion is applied consistently at matched frame times.
- Example geometric coverage is dense; the ten-percent frame cutoff is not
  material for orbit 0085.
- The code separates the main processing objects reasonably clearly and
  contains enough intermediate products to support a bounded reconstruction.

## Recommended order of work

1. Freeze current conductance products as non-publication-ready and add an
   explicit retrieval-status mask before interpreting E0 comparisons.
2. Verify the exact units, exposure normalization, flat field, temporal gain,
   calibration flag, detector state, and response-table reference epoch for
   one raw WIC/SI13 pair.
3. Form ratios only on common support at matched effective resolution; fix the
   nested SI grid and preserve signed values, masks, sample counts, and
   provenance.
4. Reproduce or falsify the Frey relation on strong-signal, near-nadir pixels
   while testing atmospheric O/N2 sensitivity.
5. Replace the fixed-proton assumption with a documented model or quantify it
   as a sensitivity, then repair the covariance and uncertainty chain.
6. Fix the independent numerical/software defects and add regression tests
   before regenerating a representative orbit.
7. Only after the representative orbit is validated, design the full dataset
   regeneration and publication versioning.

The previously chosen Zhang–Paxton replacement for E0 remains a reasonable
production direction, but it does not remove the need to audit WIC calibration
and proton correction because WIC still determines Fe. SI13 should not be
used as a validation channel until its calibration, effective resolution, and
retrieval-validity issues above are resolved.
